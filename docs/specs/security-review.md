# Security review — docsbase-memory-mcp

> Правила проведения ревью по безопасности. Дополняют `constitution.md` для всех спеков
> и задач проекта. Меняются осознанно, а не под задачу.
> Версия: 1.0.0. Дата: 2026-09-30.

## 1. Назначение и область

- Документ задаёт: модель угроз, инварианты, триггеры обязательного security-обзора,
  чеклист ревьюера, классификацию находок и обязательные доказательства.
- Область — весь продукт: daemon, CLI, MCP frontend, IPC, индексация, установка.
- Действует в дополнение к machine-mode протоколу: независимый ревьюер на задачу,
  ledger в `progress.md`, фикс-раунд для Critical/Important.

## 2. Модель угроз и границы доверия

- **Граница доверия:** MCP-клиент (агент) → frontend → daemon → файловая система.
  Агент недоверен; **граница безопасности — корень проекта** (`platform::paths::is_under`
  / `key_under`).
- **Активы:** содержимое `*.md` (может быть чувствительным), целостность индексов и
  state, доступность daemon, логи.
- **Атакующие:**
  - вредоносный/скомпрометированный агент — traversal, инъекции, флуд запросами;
  - другой локальный пользователь — доступ к сокету/pipe, чтение state;
  - злонамеренный репозиторий — symlink/junction, гигантские файлы, глубокая вложенность;
  - скомпрометированная зависимость — supply chain.
- **Вне текущей модели угроз:** pipe-ACL hardening, сетевая модель (сети нет by design),
  атаки с физическим доступом и root-привилегиями.

## 3. Инварианты — нарушение = Critical

1. **Offline.** Никакого сетевого I/O и телеметрии в рантайме; новые зависимости с сетью
   запрещены. Доказательство: `tests/offline.rs` (SC-8/NFR-5) в CI.
2. **Containment.** Каждый путь из MCP/CLI/конфига проходит канонизацию и containment:
   - *Residual (T48):* между `canonicalize` и `open` остаётся TOCTOU-окно
     (component-swap в `get_doc`/`resolve_in_root`, same-user); закрытие требует
     `openat2(RESOLVE_BENEATH)`/цепочки `O_NOFOLLOW` — кандидат на будущее.

   symlink/junction, case-fold и verbatim `\\?\` (Windows), filesystem roots. Новых
   «сырых» использований входных путей быть не должно.
3. **MD-only.** Создание/запись/чтение вне `*.md` запрещены; frontmatter — данные, не код.
4. **Кросс-проектная изоляция.** Запрос к проекту A не возвращает содержимое и метаданные
   проекта B.
5. **Права.** Каталоги 0700, state/логи/`install.json` 0600
   (`platform::fs::secure_dir/secure_file/open_private_log`); сокет — только владелец
   (0600). Windows-эквивалент — best-effort до hardening-фазы (ADR-10).
6. **Секреты.** Контент документов, чужие пути и переменные окружения не попадают в логи,
   ошибки и артефакты; наружу отдаётся минимум диагностики без содержимого.
7. **Лимиты.** У каждого входа есть cap: `search_docs.limit`/`MAX_HITS`, размер файла,
   глубина и ширина обхода, размер NDJSON-кадра, число сессий/соединений. Новые
   неограниченные пути запрещены.
8. **Fail-closed.** Сомнение в проверке безопасности (EACCES/EMFILE, неразрешимый путь,
   `root_mismatch`, `admission_lock_held`) → отказ, а не «молчаливый проход».
9. **unsafe/FFI.** Только в `src/platform/**`, с SAFETY-комментарием и инвариантным тестом;
   `interprocess`/`windows-sys` не выходят за seam (`tests/platform_boundary.rs`).
10. **Никакого shell.** `Command` — только фиксированный бинарник и литеральные аргументы;
    входные строки в args/`sh -c` не попадают. `kill -9`/`sleep` — только тестовые
    фикстуры с portability-гейтами.
11. **Недоверенная десериализация** (NDJSON, frontmatter, `meta.json`, `daemon.json`,
    `install.json`) — без паник, с лимитами, без path-побочек.

## 4. Триггеры обязательного security-обзора

Диф в любой из зон (машинно-проверяемый список — кандидат для CI):

- `src/platform/**` — транспорт, process/signals, права, пути;
- `src/ipc/**` — протокол, клиент, кадрирование;
- `src/store/**` — state, репозиторий, атомарные записи;
- `src/index/walk.rs` — обход и фильтрация файлов;
- `src/daemon/{admission,registry,lifecycle,session,server,tools}.rs`;
- `src/cli/install.rs` — установка, подмена бинаря, права;
- `src/mcp/frontend.rs` — приём запросов агента;
- `tests/platform_boundary.rs` — ослабление boundary-правил;
- `Cargo.toml`/`Cargo.lock` — новые зависимости, features, build.rs;
- изменение модели угроз → обязательная запись ADR.

## 5. Чеклист ревьюера (по диффу)

- **Вход → путь:** все ветки до `canonicalize`/`is_under`/`key_under`; нет путей, не
  прошедших containment; повторная проверка после создания (TOCTOU: state, `daemon.json`,
  `install.json`).
- **TOCTOU/расы:** проверка+открытие, rename+fsync, lease/admission, prune, watcher.
- **Windows/macOS-специфика:** verbatim/UNC пути, junction, case-fold, roots, имя pipe,
  подмена `.exe` при занятом daemon (не молчаливая).
- **DoS:** размер кадра, число сессий и соединений, глубина/ширина обхода, RSS.
- **Утечки:** ошибки наружу (MCP), логи, `status`; маскирование.
- **Deps:** источник, 14-дневный min-publish-age, лицензия, native code, отсутствие
  сети и сборки кода в build.rs.
- **Новые проверки безопасности** сопровождаются тестом, а не комментарием.

## 6. Severity и действия

- **Critical** — escape containment, кросс-проектная утечка, инъекция/RCE, сеть, утечка
  секретов, нарушение целостности данных: блокирует задачу; фикс + регресс-тест + scoped
  re-review. **Security-Critical деферрать нельзя.**
- **Important** — DoS без cap, fail-open, права, широкое TOCTOU-окно: блокирует; деферрал
  только через ADR с обоснованием и сроком.
- **Minor** — вне текущей модели угроз: `minor (deferred)` с обоснованием в ledger.

## 7. Обязательные доказательства

- Traversal-suite: `..`, абсолютный путь, symlink/junction, case-variant, `\\?\`,
  root-парадокс, `$HOME`-подмена.
- Лимиты: oversized файл/кадр/лимит поиска (`MAX_HITS`), переполнение очередей.
- Права: `stat` 0600/0700 на Unix; Windows — минимум clippy/tests под
  `x86_64-pc-windows-gnu` и линковка тест-бинарей.
- `tests/offline.rs` + `tests/platform_boundary.rs` в CI (nightly/release).
- Новые инварианты закрепляются тестом; ослабление существующего — ADR.

## 8. Процесс

- Ревьюер независим от автора (fresh subagent); Critical/Important — фикс-раунд и
  повторное ревью той же сессией.
- Ledger-метки `security:` для находок и решений; ссылка на ADR для деферралов.
- Раз в фазу: delta-аудит модели угроз + прогон чеклиста §5; при изменении поверхности —
  обновление `requirements.md`/ADR.
- Правила действуют для всех задач T1+; отступления фиксируются в `progress.md`.
